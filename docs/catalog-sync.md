# Catalog sync — `github-stars` pushes `content/catalog.json` to `main`

`content/catalog.json` (the `/links` catalog and the Lab `stars` command)
is generated by the weekly Action of the private `blindtk/github-stars`
repo. That Action **pushes** the file here, straight to `main`, and only
that file. This site never fetches anything at build time: the build
imports the vendored JSON statically and fails on a bad schema
(`static/src/lib/catalog.ts`).

```
github-stars (Mon cron) ──generate──▶ catalog/catalog.json
        │ validate shape, diff against current
        ▼
git push (deploy key) ──▶ personal-site/main  (only content/catalog.json)
        │
        ▼
Cloudflare Pages builds on push ──▶ verify-headers runs after deploy
```

## Why push, not pull

The repo is private, so a build-time fetch would need a read token in
Cloudflare Pages and would make every deploy depend on the GitHub API.
A push keeps the build offline and deterministic, and the git history
records each catalog update.

## One-time setup

1. **Deploy key.** Generate a key pair (`ssh-keygen -t ed25519 -N ''`).
   Add the public half to *this* repo (Settings → Deploy keys) with
   **write access**. Store the private half as the `PERSONAL_SITE_DEPLOY_KEY`
   secret in `github-stars`. It can write to this repo and nothing else.
2. **Ruleset bypass.** `main` requires a PR and Code Owners review, so a
   plain push is rejected (`Cannot update this protected ref`). In the
   `main` ruleset, add **Deploy keys** to the bypass list (mode: always).
   A bypass actor can push anything, so the only guard on scope is the
   workflow itself, which stages `content/catalog.json` and nothing else.
3. The `push-to-site` job lives in `github-stars`'s
   `.github/workflows/update-catalog.yml` and runs after the `catalog`
   job. It validates the shape (mirrors `assertCatalogShape()` in
   `static/src/lib/catalog.ts` — keep the two in step), clones this repo
   over the deploy key with GitHub's SSH host key pinned, copies the one
   file, and pushes to `main` only if it changed. It runs on the same
   self-hosted runner, with the key in a job-private directory removed on
   exit.

## Failure modes

| What breaks | What happens |
| --- | --- |
| Generator changes the schema | The shape check fails in `github-stars`; nothing is pushed, `main` is untouched. |
| The shape check passes but a nested field is wrong | Pages build fails on `main`; the previous deployment stays live. Fix forward in `github-stars` or revert the commit. |
| Deploy key missing from the ruleset bypass | Push is rejected; the workflow fails visibly. |
| Key leaked | It can write to this repo only: delete it in Deploy keys and rotate the secret. |
